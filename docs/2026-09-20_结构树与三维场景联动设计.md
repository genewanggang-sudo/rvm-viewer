# 结构树与三维场景联动设计

- 日期：2026-09-20
- 状态：设计定稿，待实施（本文档同时记录 SDK 0.4.0 wasm 更新与映射可行性核验结论）
- 前置：左侧「模型结构」树与右侧「属性」面板已上线（2026-09-18 方案）；树节点选中目前只驱动属性查询，与三维视图无任何联动。

## 1. 结论

1. **联动基础已具备，无需改 SDK**。经实测核验（见第 3 节）：`preview` 导出的 GLB 层级与
   `tree` 返回的 RVM 层级**逐层同名、同序、一一对应**——WD1-PSUP.RVM 全部 4677 个节点配对
   检查 0 错配，2628 个实体恰好对应 2628 个 GLB mesh。前端在加载后做一次「同序配对 DFS」
   即可建立 `RvmTreeNode ↔ THREE.Object3D` 的精确映射。
2. **映射必须用同序配对，不能用按名字查找**。真实模型里存在 443 处同名兄弟节点（多为空名
   的 SCTN 子实体），这正是 SDK 0.4.0 删除 `TreeNode.path` 的同一原因。按名字在子层中查找
   会命中错误对象；同序配对天然消歧。
3. 参考 PlantAssistant（见第 2 节），联动的本质是三件事：**选择状态共享**（双向）、
   **相机操作**（Zoom To / Center）、**可见性操作**（显示 / 隐藏 / 隔离）。建议按
   第 5 节分四期实施，P1（映射 + 树选高亮 + 定位）价值最大、改动最小。
4. 本次随 SDK 0.4.0 更新已完成 `path` 字段移除的代码适配（`rvmNodeDisplayPath()` 由
   `segments` 派生展示路径），并同步替换了 `public/rvmsdk` 与 `dist/rvmsdk` 中的
   `rvmedit.wasm`（v0.3.0 → v0.4.0-stage3）与 `rvm-sdk.d.ts`。

## 2. PlantAssistant 的做法（调研）

PlantAssistant 是 eryar 开发的 AVEVA PDMS/E3D RVM 与 Intergraph SmartPlant3D VUE 查看/转换
工具（RvmTranslator 的后继，闭源免费查看），其发布说明与博客（cppblog/cnblogs「OpenCASCADE」
系列）明确展示了结构树联动的交互形态：

| 能力 | PlantAssistant 行为 | 出处 |
|---|---|---|
| 反向联动 | 三维视图选中模型后，**自动在设计导航树上定位**该节点（展开 + 高亮） | RvmTranslator 7.6.4 之前的既有能力 |
| 正向联动 | 树节点**右键 → 定位三维模型**（相机飞到该对象）；7.6.4 专门补齐「从设计导航树上定位三维模型」 | 7.6.4 release notes |
| 显隐 | 树节点右键**显示 / 隐藏**（示例：选中保温层 Insulation Volume 结点右键隐藏保温层模型） | 7.6.4；《PlantAssistant-保温层处理》 |
| 三维右键菜单 | 空白处：Clear / Zoom All；选中模型：**Remove / Zoom To / Center**（Center 把该点设为旋转中心） | 7.6.4 release notes |
| 查找定位 | 名称查找（区分大小写、全字匹配、模糊/精确），结果**从设计导航树定位三维** | 7.5.0；《从 RvmTranslator 到 PlantAssistant》 |
| 其他 | 坐标查询；无色 RVM 的模型颜色与透明度设置；剖切范围可由选中模型反推 | 7.6.2、剖切文 |

两点工程经验值得吸收：

- 联动的中枢是**共享的「当前选择」状态**：树、三维视图、属性面板都是这个状态的视图；
  这与本项目 2026-09-18 方案里 Review 的「Explorer / 3D 视图 / Data Viewer 共享当前选择」
  结论一致。
- 作者特别记录：**PDMS 中名称工程内唯一，SP3D 中名称不唯一**——所以树定位/查找不能只依赖
  名称字符串，需要结构化的节点标识。本项目 `segments`（+ 同序配对）即结构化标识。

## 3. 映射可行性核验（本次实测）

方法：Node 环境直载 wasm 能力层（`tmp/glb-order-verify.mjs`），`open` SDK 自带样本
`samples/WD1-PSUP.RVM`，分别取 `tree` 与 `preview` GLB，解析 GLB JSON chunk 后做同序配对
DFS 逐节点比对。

| 指标 | 结果 |
|---|---|
| 配对检查节点数 | 4677（= RVM nodeCount = GLB nodes） |
| 名称/顺序错配 | **0** |
| 实体数 vs GLB mesh 数 | 2628 = 2628（1 实体 1 mesh，无合并网格） |
| 层级深度 | 7（RootNode → WORLD → SITE → ZONE/STRUCTURE → SUBSTRUCTURE → 实体） |
| 同名兄弟节点 | **443 处**（多为 `SCTN …` 组下空名实体） |

层级形状示例（GLB 与 tree 完全一致）：

```
RootNode
└─ /WD1-PSUP                       （WORLD）
   └─ /PS/WD1/0001                 （SITE/EQUIPMENT 层）
      ├─ /PS/WD1/0001/F1
      ├─ /PS/WD1/0001/F2
      │  └─ FRMWORK 1 of …
      │     └─ SCTN 1 of …   <mesh>（实体 = GLB mesh 节点）
      └─ /PS/WD1/0001/M1
         ├─ SUBSTRUCTURE 1 of …
         │  ├─ BOX 1 of …     <mesh>
         │  └─ CYLINDER 1 of …<mesh>
         └─ SUBSTRUCTURE 2 of …
```

与本项目相关的两个既有事实：

- `ViewerEngine.setObject3D()` 会把 GLTF 场景**去中心化并整体缩放**（wrapper Group）。
  因此树定位/聚焦一律用 `THREE.Box3().setFromObject(选中子树)` 在本地场景图上计算；
  wasm 的 `bbox` op 返回 RVM 世界坐标，与显示空间不一致，**不用于相机定位**。
- `ModelExplorer.nodeKey` 目前用 `JSON.stringify(segments)` 作为 React key 与展开状态键。
  443 处同名兄弟意味着空名实体会产生**重复 key**（React 警告 + 展开状态串扰）。联动实施时
  应改为「索引路径」键（见 4.1）。

## 4. 联动方案设计

### 4.1 映射构建（`src/viewer/rvmSdk.ts`，新增）

`importRvmModel` 在 GLTFLoader 解析完成后、返回会话前，与 `tree.root` 做一次同序配对 DFS：

- 树侧第 i 个孩子 ↔ GLB 侧 `children[i]`（本次已验证两侧同构同序；配对时若长度不一致，
  以告警降级——映射缺失的节点联动静默跳过，不影响加载）。
- 产出两个 **WeakMap**（随会话对象一起释放，无需手工清理）：
  - `nodeToObject: WeakMap<RvmTreeNode, THREE.Object3D>`
  - `objectToNode: WeakMap<THREE.Object3D, RvmTreeNode>`
- 会话接口增加 `resolveObject(node)` 与 `resolveNode(object)`。

### 4.2 树 → 场景（正向联动，P1）

树节点被选中时（现有 `selectNode` 链路）：

1. **高亮**：对选中子树 `traverse` 收集 mesh，换上共享的 highlight 材质（半透明橙/黄
   `MeshStandardMaterial`，depthTest 保持）；记录被换材质清单，选择变化时先还原。
   材质交换法不改原材质、可整体还原、成本低（只克隆一份高亮材质，O(选中子树 mesh 数) 次赋值）。
2. **定位（Zoom To）**：`Box3().setFromObject(选中子树)` → 相机 fit。将 `ViewerEngine`
   的 `getCameraFrame` 泛化为 `frameBox(box)`，空盒/根节点回退为现有 `frameModel`。
   是否自动定位建议做成**双击/命令触发**而非单击必飞（单击频繁飞相机会晕）——PlantAssistant
   用右键菜单「定位」，我们用树行双击 + 工具条按钮两路入口。
   **定位胜过隐藏**（已实施）：定位路径上的隐藏祖先分支会被自动恢复显示并同步隐藏
   集合——定位的意图就是"带我去看它"，目标不可见等于定位失败（Review / PlantAssistant
   同语义）；不在路径上的隐藏分支不动。
3. **Center（设旋转中心）**：`controls.target` 平移到选中盒中心，相机位置不动。二期可选。

### 4.3 场景 → 树（反向联动，P2）

1. canvas `pointerdown/pointerup` 位移 < 阈值（如 4px）判定为点击（与 OrbitControls 拖拽
   区分），Raycaster 拾取（排除背景与 helper）。
2. 命中 mesh 后沿 `parent` 链上溯，用 `objectToNode` 查第一个命中的树节点（通常是其最近
   的实体或组节点）。
3. 走现有 `selectNode(node)`（属性查询 + 高亮），树 UI 额外做两件事：
   - 把选中节点的**祖先链**加入展开集合（`ModelExplorer` 增加受控副作用 `useEffect`）；
   - 选中行 `scrollIntoView({ block: 'nearest' })`。
4. 点击空白处清除选择（回到全局态），与 AVEVA Review 一致。

### 4.4 可见性与隔离（P3）

- 树行增加显隐 checkbox（或右键菜单「隐藏/显示」）：本地 `object.visible` 子树 traverse
  切换，树 UI 以淡化样式同步。**查看器阶段不回写 wasm**（`patchNode visible` 会让
  wasm 内场景与已加载 GLB 不一致，需要重新 `preview` + 重建映射，成本高）。
- 「隔离显示」= 其余兄弟分支隐藏 + 全局 frame，纯本地组合操作。
- 名称查找（沿用 PlantAssistant 7.5.0 交互）：树内模糊匹配 + 命中列表 → 选中并定位。
  注意 SP3D 名称不唯一，命中列表按树路径展示。

### 4.5 状态与一致性

- 唯一事实源：`useViewer` 的 `selectedNode`（现有）。高亮、树滚动、属性面板都由它派生；
  反向拾取只是另一个 `selectNode` 入口。
- 重新导入/切换会话时：清空选择、显隐与映射（WeakMap 随会话丢弃；`applyDefaultDisplayMaterials`
  与高亮还原都作用于旧 object，随 `engine.clear()` 一并释放）。
- `ModelExplorer.nodeKey` 从 `JSON.stringify(segments)` 改为**索引路径**
  （如 `parentKey + '/' + index`），同名兄弟不再撞键；SDK 寻址仍用 `segments` 不变。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 同名兄弟节点（443 处实测）导致按名映射错位、UI key 冲突 | 同序配对 DFS（已验证 0 错配）；UI key 改索引路径 |
| GLB 与 tree 结构在异构文件上不一致（理论风险，仅验证了 WD1-PSUP） | 配对时校验孩子数，不一致即降级告警、联动跳过；后续每接入新样本跑 `tmp/glb-order-verify.mjs` |
| 大模型高亮/拾取性能 | 高亮只操作选中子树；拾取 Raycaster 对 2628 mesh 可接受，卡顿再引入 three-mesh-bvh |
| wrapper 去中心化/缩放导致坐标错位 | 相机与包围盒一律本地 `Box3.setFromObject`，不使用 wasm `bbox` 世界坐标 |
| 单击即飞相机造成操作眩晕 | 定位用双击/按钮显式触发，单击只做选择+高亮 |
| 本地显隐与 wasm 场景状态漂移 | 查看器阶段显隐只存 three.js 本地状态；编辑持久化统一放 P4（patchNode + 重预览 + 重建映射） |
