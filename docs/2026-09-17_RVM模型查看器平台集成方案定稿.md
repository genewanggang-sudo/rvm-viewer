# RVM 模型查看器平台集成方案

- 日期：2026-09-17
- 状态：实现完成，待真实 AIDT HTTPS 部署后的端到端验收
- 范围：AIDT 聊天中的模型上传、薄 HTML 交付和外部静态 viewer 展示

## 目标与边界

项目不是在 AIDT 内直接托管大型 WebGL 应用，而是由智能体交付一个小 HTML 文件。预览页将该文件以 `srcdoc` 打开，HTML 再嵌入独立部署的 HTTPS viewer。前端没有后端、数据库或上传 API。

支持范围：OBJ、STL 和 RVM（可选 ATT）；RVT 不在浏览器直接解析范围内，需先从 Revit 导出 IFC、OBJ 或 GLB。

## 三条数据通道

| 模式 | 输入 | 交付件内容 | viewer 取数 |
| --- | --- | --- | --- |
| `payload` | 小型 OBJ/STL 几何 | base64url 几何在 iframe URL | 解码后直接渲染 |
| `postmsg` | 较大 OBJ/STL 几何 | 几何嵌入薄 HTML | viewer ready 后由父页注入 |
| `fileref` | RVM/ATT 工作区文件 | 文件相对路径，不嵌入原文件 | viewer 拉取原始 bytes，交给 Worker/WASM |

通道优先级为 `payload > file > demo > postMessage`；命中 URL 通道后忽略后续消息，避免同一模型被重复渲染。

## fileref 的路径规则

早期设计把 `media/<uuid>_model.rvm` 直接作为外部 viewer 的 `file` 参数。这是错误的：相对 URL 会以 viewer 静态站为基地址，最终指向错误域名。

现在薄 HTML 在 AIDT 预览上下文中执行下列逻辑：

```js
const viewer = new URL(VIEWER_URL);
viewer.searchParams.set('file', new URL(FILE_REF, document.baseURI).href);
viewer.searchParams.set('att', new URL(ATT_REF, document.baseURI).href);
frame.src = viewer.href;
```

`document.baseURI` 由 AIDT 预览页提供，因此 `media/...` 先解析为平台文件服务的绝对地址，viewer 再以 `credentials: 'include'` 请求该地址。该步骤已在生成 HTML 中验证；真正平台环境的 CORS、Cookie SameSite 和 sandbox 行为尚未验收。

## RVM 实现

前端的 `src/viewer/rvmSdk.ts` 经 `public/rvmsdk/rvm-rpc.js` 创建 Worker RPC，传递 RVM 和可选 ATT `ArrayBuffer`，再将生成的 GLB 场景交给 `GLTFLoader` 和 `ViewerEngine`。RVM 不是“解析器待接入”的占位分支。

## 部署和验收

1. 选择稳定的 HTTPS viewer URL。
2. 运行 `corepack pnpm@10.12.1 prepare:aidt -- --viewer-url <url>` 生成 `tmp/aidt-release/`。
3. 将 `viewer/` 发布到该 URL，将生成的 `agent/` 压缩上传到 AIDT。
4. 在默认平台模型下验证 OBJ payload、OBJ postMessage、RVM/ATT fileref 三条链路。
5. 对 fileref 记录 Network 中文件请求的 URL、状态码、响应类型和 Cookie/CORS 错误（若有）。

只有第 4、5 项通过后，才能称为 AIDT 平台 E2E 完成。平台上传、工作区落盘和预览 `srcdoc` 行为来自已有调研记录；本仓库当前没有配置真实 HTTPS URL，因此没有把该调研替代为交付验收。
