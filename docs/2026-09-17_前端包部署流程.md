# RVM Viewer 前端包部署流程

- 日期：2026-09-17
- 适用范围：将 `frontend/` 构建出的纯静态前端发布到现有 Nginx 子目录
- 生产地址：`https://www.czy3d.com/sample/rvm-viewer/`
- 当前状态：生产页面及其 JS、CSS、RVM SDK、WASM 已验证可访问

## 1. 固定部署参数

| 项目 | 值 |
| --- | --- |
| Vite `base` | `/sample/rvm-viewer/` |
| 对外 URL | `https://www.czy3d.com/sample/rvm-viewer/` |
| 服务器 | `118.178.127.234:22` |
| 协议 | SFTP（SSH 公钥认证） |
| 用户名 | `wanggang-html` |
| 远端目录 | `/var/lib/docker/volumes/cc_nginx_data/_data/html/sample/rvm-viewer` |

前端部署在子目录，不是域名根目录。因此 `frontend/vite.config.ts` 必须保持：

```ts
base: '/sample/rvm-viewer/',
```

如果误用 `base: '/'`，构建后的页面会请求 `/assets/...` 和 `/rvmsdk/...`，浏览器将去
域名根目录找资源，页面即使返回 200 也无法正常启动。

## 2. 构建前检查

环境要求为 Node.js `>=20.19.0`、pnpm `10.12.1`。在仓库中执行：

```powershell
Set-Location D:\work\rvm-viewer\frontend
corepack pnpm@10.12.1 install --frozen-lockfile
corepack pnpm@10.12.1 verify
```

`verify` 会依次执行格式、ESLint、TypeScript、类型覆盖率、单元测试和生产构建。只有全部
通过后才使用生成的 `frontend/dist/`。生产包必须包含以下结构：

```text
dist/
  index.html
  assets/
  rvmsdk/
    rvm-rpc.js
    rvm-worker.js
    rvm-wasm.js
    rvmedit.wasm
    ...
```

`tmp/testdata/` 中的测试 RVM 不得出现在生产包中。

## 3. 单独构建与打包

如果前面的 `verify` 已成功，`dist/` 已是最新构建；需要单独重建时执行：

```powershell
Set-Location D:\work\rvm-viewer\frontend
corepack pnpm@10.12.1 build
```

打包时压缩 `dist` 里面的内容，不要额外套一层 `dist/`，否则服务器路径会多一级：

```powershell
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
$archive = "D:\work\rvm-viewer\tmp\deploy\rvm-viewer-production-subpath-$stamp.zip"
New-Item -ItemType Directory -Force -Path (Split-Path $archive) | Out-Null
Compress-Archive -Path 'D:\work\rvm-viewer\frontend\dist\*' -DestinationPath $archive
```

`tmp/deploy/` 和 `frontend/dist/` 都是生成物，不提交到 Git。历史上使用根路径构建的旧包
不适用于当前生产地址，不能重新上传。

打包后先检查 `dist/index.html`。其中的资源 URL 应全部以 `/sample/rvm-viewer/` 开头：

```powershell
Select-String -Path D:\work\rvm-viewer\frontend\dist\index.html `
  -Pattern '/sample/rvm-viewer/'
```

## 4. 上传到服务器

本机凭据目录为 `D:\work\服务器配置\wanggang-html\`。私钥和密码属于机器凭据，不能
复制到仓库、部署包或文档附件中。

使用 WinSCP 或其他 SFTP 客户端连接：

```text
协议：SFTP
主机：118.178.127.234
端口：22
用户：wanggang-html
私钥：D:\work\服务器配置\wanggang-html\id_rsa_2048
```

进入远端目录：

```text
/var/lib/docker/volumes/cc_nginx_data/_data/html/sample/rvm-viewer
```

将本地 `frontend/dist/` 内的 `index.html`、`assets/` 和 `rvmsdk/` 上传到该目录并覆盖
同名内容。上传的是解压后的内容，不是 ZIP/RAR 文件，也不是外层 `dist` 目录。

覆盖前应保留当前线上版本的可恢复副本；如果账号没有创建备份、覆盖或进入目标目录的
权限，停止操作并让服务器管理员处理，不要改传到其他目录。

## 5. 线上验收

上传后至少验证以下四项：

1. 生产 URL 返回 200，页面不是目录列表或旧版本。
2. `index.html` 引用的 JS、CSS 和 `rvmsdk/rvm-rpc.js` 均位于
   `/sample/rvm-viewer/` 下并返回 200。
3. `/sample/rvm-viewer/rvmsdk/rvmedit.wasm` 返回 200，`Content-Type` 为
   `application/wasm`。
4. 浏览器实际打开页面后没有静态资源 404，选择一个 RVM 能完成解析和渲染。

PowerShell 快速检查：

```powershell
$base = 'https://www.czy3d.com/sample/rvm-viewer/'
$page = Invoke-WebRequest -Uri $base -UseBasicParsing
$page.StatusCode
$page.Content | Select-String '/sample/rvm-viewer/(assets|rvmsdk)/'

$wasm = Invoke-WebRequest `
  -Uri 'https://www.czy3d.com/sample/rvm-viewer/rvmsdk/rvmedit.wasm' `
  -UseBasicParsing
$wasm.StatusCode
$wasm.Headers['Content-Type']
```

2026-09-17 的复核结果为：页面、JS、CSS、`rvm-rpc.js` 和 `rvmedit.wasm` 均返回
200；WASM 的 MIME 类型为 `application/wasm`。

## 6. 回滚

若新版本出现资源 404、WASM 加载失败或模型无法打开，恢复覆盖前备份的 `index.html`、
`assets/` 和 `rvmsdk/`，然后重新执行第 5 节验收。不要只回滚 `index.html`：HTML 中带
哈希的资源名必须与对应的 `assets/` 内容保持一致。

## 7. SFTP 登录故障

2026-09-17 的诊断中，服务器网络和 SSH 端口可达，但本机使用现有 RSA 私钥登录
`wanggang-html` 时，服务器在接受公钥后仍拒绝完成认证；服务器也没有开放密码认证。
如果再次出现：

```text
Permission denied (publickey,gssapi-keyex,gssapi-with-mic)
```

这不是重新打包前端能解决的问题。请服务器管理员检查：

- `wanggang-html` 账号是否存在、未锁定、未过期并允许 SFTP；
- `/home/wanggang-html/.ssh/authorized_keys` 是否包含对应 `.pub` 公钥；
- home、`.ssh` 和 `authorized_keys` 的所有者及权限；
- `sshd` 的 `AllowUsers`、`DenyUsers`、`Match` 和 PAM 策略；
- 服务端认证日志中的实际拒绝原因。

不要使用旧脚本中的 `wangxinrui-html`，正确生产账号是 `wanggang-html`。

## 8. 与 AIDT 天赋包发布的关系

上述步骤只部署前端静态 viewer。部署成功后，如需生成与该地址绑定的 AIDT 天赋包，再
执行：

```powershell
Set-Location D:\work\rvm-viewer\frontend
corepack pnpm@10.12.1 prepare:aidt -- `
  --viewer-url https://www.czy3d.com/sample/rvm-viewer/
```

该命令在 `tmp/aidt-release/<timestamp>/` 生成 `viewer/`、`agent/` 和
`manifest.json`。其中 `viewer/` 是同类静态部署内容，`agent/` 才是上传到 AIDT 的天赋
包源码。前端上线成功不等于 AIDT 端到端通过；仍需在真实 AIDT 登录态中上传 RVM，验证
外部 viewer 对平台文件 URL 的 CORS、Cookie 和权限行为。
