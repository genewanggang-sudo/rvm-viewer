# 前端环境配置与调试 UI 收口实施方案

- 日期：2026-09-18
- 状态：待实施
- 目标：本地开发与 AIDT 使用同一套模型查看核心 UI；本地调试入口只在开发环境出现，生产构建自动移除

## 1. 结论：需要修改什么

当前实现只有部分符合要求：

- “加载测试 RVM”已经通过 `import.meta.env.DEV` 限制在开发模式。
- AIDT 薄页会传入 `embed=1` 和 RVM 文件 URL，复用同一个 React viewer。
- 但 `embed=1` 目前同时隐藏状态栏、模型信息、相机工具和本地文件面板，导致 AIDT 与本地查看界面不一致。
- Vite `base` 固定为 `/sample/rvm-viewer/`，没有通过开发/生产配置区分本地根路径与线上子路径。
- 本地文件选择和测试模型属于开发入口，当前只隐藏了测试按钮，生产环境直接访问 viewer 时仍会出现本地文件选择面板。
- AIDT 薄 HTML 自带常驻状态栏。如果嵌入 viewer 恢复核心状态栏，会产生两层状态栏，需要一并收口。

必须完成以下五项修改：

1. 用 Vite 环境文件配置开发和生产的 `base`、开发 UI 开关。
2. 将界面拆成“核心查看 UI”和“开发数据入口 UI”。
3. `embed=1` 只隐藏开发数据入口，不再隐藏核心查看 UI。
4. AIDT 薄页的外层状态条只负责启动/错误提示，模型加载成功后自动收起。
5. 增加开发、生产、AIDT 三种模式的自动化与浏览器验收。

## 2. UI 边界

### 2.1 所有环境都保留的核心 UI

以下内容在本地开发、生产独立页面和 AIDT 嵌入页中使用同一套组件：

- three.js 模型画布；
- 加载、解析、成功、失败状态；
- 模型名称、顶点数、三角面数等信息；
- “适配模型”和“恢复等轴视图”相机工具；
- 错误提示；
- 鼠标旋转、缩放和平移交互。

这部分不能根据 `embed=1` 整体删除，否则 AIDT 看到的不是与本地一致的 viewer。

### 2.2 仅开发环境显示的 UI

以下内容属于本地开发和调试入口，生产构建及 AIDT 中必须隐藏：

- 本地 RVM 文件选择器；
- “加载所选 RVM”按钮；
- “加载测试 RVM”按钮；
- 测试样本说明、开发路径提示；
- 后续新增的性能、协议或诊断面板。

生产构建不仅要隐藏测试按钮，还要隐藏整个本地文件加载面板。

## 3. 环境配置设计

采用 Vite 标准环境文件：

```text
frontend/.env.development
frontend/.env.production
frontend/.env.local
frontend/.env.example
```

其中 `.env.development` 和 `.env.production` 提交到 Git，作为团队统一配置；
`.env.local` 只用于个人覆盖，继续由 Git 忽略。

### 3.1 开发配置

`frontend/.env.development`：

```dotenv
VITE_RVM_BASE_PATH=/
VITE_RVM_ENABLE_DEV_UI=true
VITE_RVM_VIEWER_TITLE=RVM Viewer
VITE_RVM_MAX_LOCAL_FILE_MB=100
```

### 3.2 生产配置

`frontend/.env.production`：

```dotenv
VITE_RVM_BASE_PATH=/sample/rvm-viewer/
VITE_RVM_ENABLE_DEV_UI=false
VITE_RVM_VIEWER_TITLE=RVM Viewer
VITE_RVM_MAX_LOCAL_FILE_MB=100
```

### 3.3 本地覆盖

开发者可在不提交的 `frontend/.env.local` 中临时覆盖公开配置，例如端口外的标题或文件大小。
任何 `VITE_` 变量都会进入浏览器构建产物，禁止放入令牌、Cookie、密码或平台密钥。

### 3.4 Git 忽略规则

根 `.gitignore` 当前会忽略所有 `.env.*`，因此实施时需要为团队配置添加例外：

```gitignore
.env
.env.*
!.env.example
!frontend/.env.development
!frontend/.env.production
```

`.env.local`、`.env.development.local` 和 `.env.production.local` 仍保持忽略。

## 4. 配置实现

### 4.1 `frontend/vite.config.ts`

改为函数式配置，并使用 `loadEnv(mode, process.cwd(), '')` 读取环境文件：

- `base` 来自 `VITE_RVM_BASE_PATH`；
- 开发默认 `/`，生产默认 `/sample/rvm-viewer/`；
- 对路径进行规范化，保证以 `/` 开头和结尾；
- 测试 RVM 中间件只在 `command === 'serve'` 且开发 UI 开启时注册；
- `build` 中不复制 `tmp/testdata/`，保持测试模型不进入生产包。

禁止继续把生产子路径直接写死在 `base` 字段中。

### 4.2 `frontend/src/config.ts`

扩展公开运行配置：

```ts
interface RuntimeConfig {
  title: string;
  maxLocalFileBytes: number;
  devUiEnabled: boolean;
}
```

推荐使用双重约束：

```ts
devUiEnabled = import.meta.env.DEV && VITE_RVM_ENABLE_DEV_UI === 'true'
```

这样即使生产环境误配置 `VITE_RVM_ENABLE_DEV_UI=true`，生产构建也不会显示开发入口。
布尔值必须显式解析，不使用 `Boolean('false')` 之类会把字符串 `false` 当成真的写法。

## 5. React 界面调整

### 5.1 `frontend/src/App.tsx`

将当前 `!embed` 总开关拆开：

- `showDevUi = runtimeConfig.devUiEnabled && !embed`；
- `StatusBar`：所有模式显示；
- `Hud`：模型加载成功后所有模式显示；
- `CameraToolbar`：所有模式显示，未加载时禁用；
- `ErrorOverlay`：所有模式显示；
- `LocalFileLoader`：仅 `showDevUi` 时显示；
- 本地“等待模型”空状态：开发模式可以保留；生产或 AIDT 等待 URL 文件时使用简洁核心状态，不展示开发引导。

`embed=1` 的含义收敛为“文件由宿主提供，不显示本地数据入口”，而不是“隐藏整个 viewer UI”。

### 5.2 组件职责

保持以下组件为核心组件，不复制 AIDT 专用版本：

- `StatusBar.tsx`
- `Hud.tsx`
- `CameraToolbar.tsx`
- `ErrorOverlay.tsx`

`LocalFileLoader.tsx` 明确归类为开发入口。若以后新增调试面板，也统一挂在 `devUiEnabled` 下，
不允许在组件内部零散读取 `import.meta.env`。

## 6. AIDT 薄页调整

修改 `agent/scripts/pack_thin_html.mjs`：

- 继续向 viewer 传入 `file`、`name` 和 `embed=1`；
- 不创建另一套模型 UI，不复制 React viewer 的状态、HUD 或相机控制；
- 外层状态条只显示“连接 viewer”“读取文件”和启动错误；
- 收到可信 iframe 的 `rvm-viewer:rendered` 后隐藏外层状态条，并将 iframe 扩展为全高；
- 超时或启动失败时恢复状态条和重试按钮；
- 保留 `event.origin` 与 `event.source === frame.contentWindow` 校验。

这样 AIDT 中模型加载成功后，用户看到的是与本地相同的 viewer 核心界面，不会出现双层状态栏。

## 7. 模式矩阵

| 场景 | 访问方式 | 核心 UI | 本地文件入口 | 测试 RVM | 文件来源 |
| --- | --- | --- | --- | --- | --- |
| 本地开发 | `pnpm dev`，访问 `/` | 显示 | 显示 | 显示 | 本地选择或开发样本 |
| 生产独立页 | 构建后访问 `/sample/rvm-viewer/` | 显示 | 隐藏 | 隐藏 | `?file=` URL |
| AIDT 嵌入页 | `?file=...&name=...&embed=1` | 显示 | 隐藏 | 隐藏 | AIDT 工作区文件 URL |

三种模式只允许“数据入口和部署路径”不同，渲染器、模型信息和相机交互必须共用实现。

## 9. 实施顺序

1. 添加环境文件并调整 `.gitignore`。
2. 改造 `vite.config.ts`，先解决开发根路径和生产子路径。
3. 扩展 `runtimeConfig`，补齐配置单元测试。
4. 重构 `App.tsx` 的 UI 显示条件，补齐组件测试。
5. 调整薄 HTML 外层状态条和成功收起逻辑。
6. 运行完整质量门禁和三模式浏览器验收。
7. 重新生成生产 viewer 包和 AIDT 天赋包。
8. 在真实 AIDT 普通聊天中上传 RVM，完成最终对比验收。

## 10. 验收标准

### 10.1 自动化检查

```powershell
Set-Location frontend
corepack pnpm@10.12.1 verify
```

必须通过格式、Lint、TypeScript、类型覆盖、测试覆盖和生产构建。

新增断言至少包括：

- development + dev UI 开启时显示本地加载和测试按钮；
- production 即使误设开发 UI 开关也不显示调试入口；
- `embed=1` 隐藏本地加载入口，但仍显示状态栏、HUD、错误提示和相机工具；
- 生产构建资源、SDK 和 Worker URL 都位于 `/sample/rvm-viewer/` 下；
- 开发服务器从 `http://127.0.0.1:5173/` 正常打开，不依赖生产子路径；
- 生产包不包含测试 RVM 文件。

### 10.2 浏览器验收

固定相同窗口尺寸，分别截图并比较：

1. 本地开发加载测试 RVM 后的界面；
2. 生产预览以 `?file=...&embed=1` 加载同一模型后的界面；
3. AIDT 普通聊天上传同一 RVM 后的界面。

验收条件：

- 模型画布、状态栏、模型信息和相机工具的位置与样式一致；
- AIDT 不出现本地文件选择、测试按钮或开发提示；
- AIDT 外层连接状态条在成功后消失；
- 旋转、滚轮缩放、适配模型和等轴复位均可用；
- 页面无资源 404、Worker 路径错误或重复状态栏。

## 11. 不在本次范围

- 不修改 RVM Worker/WASM 的解析协议；
- 不新增后端、上传接口或模型代理；
- 不改变 AIDT 工作区文件 URL 的解析逻辑；
- 不处理 CADC TXT 属性面板；
- 不制作独立的 AIDT 专用 viewer 页面。

本次工作的核心是配置和 UI 边界收口，不是重写模型查看器。
