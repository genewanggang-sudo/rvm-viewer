# 前端 React 工程架构

- 日期：2026-09-17
- 状态：已实施并纳入自动质量门禁

## 分层

```text
protocol.ts
  -> channels/dataChannels.ts
  -> hooks/useViewer.ts
  -> viewer/ViewerEngine.ts + viewer/rvmSdk.ts
  -> App.tsx + components/
```

- `protocol.ts`：URL 参数、消息类型、几何校验和共享类型。
- `channels/`：仲裁 payload、file、demo、postMessage 四条入口，并处理文件读取与回执。
- `hooks/`：管理 React UI 状态、本地上传和引擎生命周期。
- `viewer/`：three.js 命令式渲染内核、OBJ/STL 解析、RVM Worker/WASM 适配。
- `components/`：状态栏、HUD、错误展示和本地上传控件，不承担协议或渲染逻辑。

选择 React 管 UI、three.js 独立为类，避免将数据协议、渲染资源释放和 React 组件生命周期耦合；以后替换渲染内核时不需要改变交付协议。

## 工程约束

- TypeScript 严格模式，`type-coverage` 最低阈值为 100%。
- ESLint Flat Config 和 Prettier 管理前端源码与测试。
- Vitest + Testing Library 覆盖协议、通道、解析器、RVM SDK 适配、渲染引擎、Hook、App 与组件。
- `pnpm verify` 是唯一完整本地门禁：格式检查、lint、类型检查、类型覆盖、测试覆盖、生产构建。

## 本地能力

首页提供手动上传，无需 AIDT 即可验证 OBJ、ASCII/Binary STL 和 RVM 基本加载。RVM 使用项目随部署携带的 Worker/WASM 资源；运行时错误展示在页面状态层，不让失败的 Promise 留在界面外。

`?demo=1` 加载内置演示模型，`?embed=1` 隐藏普通 UI。生产构建输出 `frontend/dist/`，属于生成物且被 Git 忽略。
