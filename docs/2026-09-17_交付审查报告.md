# RVM Viewer 交付审查报告

- 日期：2026-09-17
- 审查范围：当前工作区的前端、天赋源码、发布准备、文档和 Git 卫生

## 已完成

| 项目 | 结论 |
| --- | --- |
| 前端工程 | React/Vite/严格 TypeScript 已落地；本地 OBJ、STL、RVM/ATT 上传走真实渲染路径。 |
| RVM 支持 | Worker/WASM 适配已接入 `useViewer`，不再依赖“待解析”占位分支。 |
| 数据通道 | payload、postMessage、file、demo 均有明确优先级和协议回执。 |
| fileref 修复 | 薄 HTML 将 `media/...` 解析为 AIDT 绝对文件 URL 后再设置 viewer iframe。 |
| 本地质量 | 通过 `pnpm verify` 后可确认格式、lint、严格类型、100% 类型/测试覆盖和构建。 |
| 发布准备 | `scripts/prepare-aidt-release.mjs` 在 `tmp/aidt-release/` 生成静态部署目录、已配置的天赋副本及 SHA-256 清单，且不修改源码。 |
| Git 卫生 | `tmp/` 被根 `.gitignore` 忽略；日志、截图、浏览器 profile、旧 ZIP 和一次性 CDP 脚本已收口到该目录。 |

## 未完成的外部验收

1. 需要用户提供并部署真实 HTTPS viewer URL。
2. 需要在 AIDT 默认模型的真实聊天中验证 OBJ payload、OBJ postMessage、RVM/ATT fileref。
3. 重点观察外部 viewer 对 AIDT 绝对文件 URL 的 CORS、Cookie SameSite、认证和 sandbox 限制。

## 影响与下一步

代码与发布材料可以在本地复现，但不能把本地验证等同于平台 E2E。完成静态部署后，以实际 URL 生成发布目录并上传天赋；若 fileref 请求失败，应保留 Network 证据到 `tmp/evidence/`，再根据平台返回的 CORS/认证限制决定是否需要平台代理。
